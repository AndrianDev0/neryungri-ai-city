# Neryungri AI City

Локальный учебный прототип для анализа обращений жителей Нерюнгри. Python, FastAPI, SQLite, scikit-learn и JavaScript API Яндекс Карт 2.1.

Исследовательская задача: выявлять повторяющиеся проблемы и оценивать ожидаемую нагрузку городских служб по обезличенным обращениям. Польза рекомендаций должна проверяться на реальной истории и результатах осмотров; текущая версия её не доказывает.

## Учёт проблем и повторов

В карточке обращения можно вручную связать его с другой открытой проблемой той же категории. Сообщения не удаляются. Связанные записи имеют общий статус, категорию и приоритет; при объединении сохраняется наибольший приоритет. Отдельный дубль можно отсоединить, сохранив его текущие значения. Группы целиком не объединяются: сначала отделите конкретную запись. Карта и реестр по-прежнему показывают обращения, а не отдельные проблемы.

«Решено» и «Ремонт подтверждён проверкой» различаются. Подтверждение требует описания результата. Дата решения фиксируется при сохранении; для старых записей дата ремонта не выдумывается. Новая поломка связывается с предыдущей только после подтверждённого ремонта и при более поздней дате обращения. Такая связь не объединяет две проблемы. До снятия связи нельзя отменить ремонт или изменить категорию её участников.

В аналитике отдельно считаются сообщения, учётные проблемы, дубли и повторные поломки. Сектор группы берётся по основной записи. Несвязанные записи считаются отдельными проблемами: итог зависит от ручной проверки и не является числом всех городских неисправностей.

## Проверка прогноза

При наличии 56 дней истории и 60 сообщений приложение проверяет общий недельный объём на четырёх прошедших семидневных отрезках. На каждом используется только предыдущая история. Среднее за четыре недели сравнивается с правилом «столько же, сколько на прошлой неделе» по средней абсолютной ошибке (MAE). Сегодняшний неполный день в проверку не включается. Полнота истории предполагается; отсутствие записей считается нулём. Учебные результаты не подтверждают качество на реальных данных.

Оценки по категориям и условным секторам являются отдельными разрезами, не совместным прогнозом «категория × сектор». Ошибка измеряется только для общего числа сообщений. Дубли включены, поскольку оценивается входящий поток, а не число поломок.

Следующий исследовательский этап требует обезличенной городской истории: независимая оценка классификации, проверка связанных дублей специалистом, сезонные признаки и сопоставление рекомендаций с результатами осмотров. Погодные зависимости и вероятность аварий пока не реализованы.

## Запуск

### Публикация на GitHub Pages и Render

GitHub Pages размещает интерфейс, Render Free запускает Python. `render.yaml` описывает
бесплатный сервер. В GitHub Actions используется переменная репозитория `API_BASE`
с HTTPS-адресом сервера. После её заполнения запустите workflow `Publish website`.
Сборка `scripts/build_pages.py` включает только браузерные файлы из `static`.

На сервере задаются `NERYUNGRI_ALLOWED_ORIGINS` (точный адрес сайта без пути),
`NERYUNGRI_YANDEX_MAPS_API_KEY`, `NERYUNGRI_PUBLIC=1` и `NERYUNGRI_WRITE_TOKEN`
(случайный код длиной не менее 32 символов). Код редактирования нельзя помещать
в конфигурацию Pages или Git. При сохранении сайт запросит его и запомнит до
закрытия вкладки. Просмотр данных и анализ текста доступны без кода.

Бесплатный сервер использует временную SQLite: новые обращения и фотографии
могут исчезнуть при перезапуске, повторной публикации и остановке после простоя.
Учебные примеры создаются заново. Все опубликованные записи и фотографии открыты
для просмотра; используйте только обезличенные или вымышленные данные.
После простоя запуск сервера может занять около минуты.

Для Яндекс Карт добавьте `andriandev0.github.io` и домен сервера в разрешённые
HTTP Referer в кабинете Яндекса. Сохраните `localhost` для локальной разработки.

### На своём компьютере

В Windows откройте `Start.cmd`, затем перейдите на http://localhost:8765.
При каждом запуске проверяются версии из `requirements-lock.txt`. Если установка была прервана или пакет отсутствует, запуск повторит установку. При исправном окружении скачивание не требуется.
Сервер работает, пока открыто окно запуска. Для остановки нажмите Ctrl+C.

На другом компьютере нужен Python 3.12 или новее. Команды ручного запуска:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

## Подключение Яндекс Карт

1. Откройте https://developer.tech.yandex.ru/, нажмите «Подключить API» и выберите **JavaScript API**.
2. В настройках ключа заполните «Ограничение по HTTP Referer»: `localhost`, без схемы и порта. IP-адрес `127.0.0.1` в этом поле не принимается. Для размещённого сайта добавьте его домен.
3. В папке проекта откройте `config.local.toml`. Если файла нет, скопируйте `config.example.toml` под этим именем. Вставьте ключ между кавычками:

```toml
yandex_maps_api_key = "ваш ключ"
```

4. Сохраните файл и обновите страницу приложения. Перезапуск сервера не нужен. Активация ключа и изменение ограничений могут занять до 15 минут.

Альтернатива для запуска: переменная окружения `NERYUNGRI_YANDEX_MAPS_API_KEY`, которая имеет приоритет над файлом.
Ключ JavaScript API доступен браузеру по назначению. Ограничьте его разрешёнными адресами в кабинете Яндекса; не используйте здесь серверные секреты. Локальный файл исключён из Git, API настроек возвращает только ключ карты.

Без ключа или при ошибке загрузки SDK вместо карты показывается сообщение с инструкцией. Реестр, фильтры, анализ текста и ввод координат работают отдельно от карты. Приложение не использует чужие демонстрационные ключи и не переключается на другого поставщика карт.

Для бесплатного использования применяются условия Яндекса: https://yandex.ru/dev/commercial/doc/ru/. Для закрытого рабочего кабинета нужно отдельно подобрать подходящую лицензию.

## Данные и ограничения

- «Учебные» содержит 18 вымышленных обращений с иллюстративными точками. Названия улиц в описаниях не являются результатом адресного геокодирования. Примеры не отражают состояние города.
- «Добавленные» изначально пусты. Добавленные и импортированные обращения сохраняются отдельно в `data/city.sqlite3`. На опубликованном сервере они видны всем посетителям.
- Классификатор TF-IDF + логистическая регрессия обучен на 84 авторских учебных фразах. Его качество на реальных обращениях не измерено. Исправление категории изменяет запись, но пока не переобучает модель.
- Срочность определяют прозрачные правила по тексту; специалист может изменить результат. Упоминание опасности может быть ошибочным или отрицательным, поэтому нужна проверка.
- Координаты задаёт пользователь на карте либо передаёт при импорте. Приложение не выдумывает координаты по одному тексту и не отправляет обращения внешним языковым моделям.
- Секторы «Север / середина» и подобные обозначают условные зоны анализа, а не официальные административные границы.
- Похожие обращения: одинаковая категория, расстояние до 120 м и разница дат до 7 суток. Это подсказка, автоматического объединения нет.
- Прогноз доступен при истории от 28 завершённых дней и 30 обращений до сегодняшнего дня. Это среднее за последние четыре полные недели, при допущении полноты выгрузки. Сегодняшний неполный день исключён из прогноза и проверки его точности. Прогноз не является проверенной моделью аварий или вероятностью повторной поломки. Дубликаты могут увеличивать оценку числа сообщений.
- Даты интерпретируются в UTC+9. Графики строятся по дате обращения.
- Яндекс Карты загружаются через интернет. Картографический адаптер преобразует координаты в порядок «широта, долгота», который использует API 2.1; в базе и CSV поля `lat` и `lon` сохраняют свои значения. Автоматическое геокодирование не подключено.
- Прототип предназначен для локального использования. Для публичного запуска нужны учётные записи, контроль доступа, регламент обработки данных и отдельная проверка эксплуатации.

## Импорт

CSV в UTF-8: обязательный столбец `text`; необязательные `address`, `lat`, `lon`, `category`, `created_at`.
Разделитель: запятая, точка с запятой или табуляция. Не более 500 строк за загрузку.
Категории: `snow`, `lighting`, `waste`, `roads`, `drainage`, `other`.
Дата: ISO 8601, например `2026-10-01T12:00:00+09:00`. Без часового пояса используется UTC+9.
Шаблон можно скачать в окне импорта. Все строки проверяются до сохранения: при ошибке файл целиком отклоняется.
Число ячеек должно совпадать с заголовком, даже если необязательные значения пустые. Текст с разделителем или переносом строки заключайте в двойные кавычки. Повторяющиеся заголовки и повреждённые кавычки отклоняются с сообщением об ошибке.
Выгрузку учебного набора с `demo=true` нельзя загрузить в «Добавленные»: приложение отклоняет весь такой файл, сохраняя разделение наборов.
Выгрузка включает статус, приоритет, идентификаторы связей и сведения о проверке ремонта для анализа. Повторный импорт создаёт новые записи: он не восстанавливает связи и историю ремонта, статус и приоритет рассчитываются заново. CSV не является резервной копией базы. Импорт не устраняет дубликаты автоматически.

## Проверка

В карточке можно назначить ответственного и плановый срок, исправить адрес и координаты,
прикрепить фотографии до/после ремонта и просмотреть историю изменений. Статус, категория,
приоритет, ответственный и срок общие для группы дублей. Адрес, координаты и фотографии
относятся к конкретному обращению. При присоединении дубля ответственный и срок берутся
из выбранной существующей проблемы; более высокий приоритет сохраняется.

Черновики правок карточек хранятся в памяти вкладки до обновления страницы. Они сохраняются
при закрытии карточки, переходе к другой записи и изменении связей. Кнопка «Сбросить правки»
отменяет черновик. При обновлении страницы браузер предупреждает о несохранённых правках.

При нескольких распознанных темах кнопка «Разобрать обращение» предлагает отдельные задачи.
Оператор проверяет текст и категорию каждой задачи; исходное сообщение сохраняется вместе
со связью между ними. Это эвристическое предложение учебной модели, возможны пропуски.
Правила приоритета учитывают некоторые отрицания и сообщения об устранении в той же фразе;
они не заменяют проверку специалистом и не закрывают обращение автоматически.

Режим карты «Проблемы без дублей» показывает одну точку по основной записи группы. Фильтр
находит группу по любому подходящему сообщению; если в основной записи нет координат, точки
группы на карте нет. Реестр и список продолжают показывать отдельные сообщения.

История начинается с включения этой функции и содержит значения до/после, без авторства:
в локальном прототипе нет аккаунтов. Фото (до 12 на обращение, до 5 МБ и 20 Мп каждое)
хранятся в SQLite, преобразуются в JPEG до 2400 px с удалением EXIF. Фото сохраняются
сразу, отдельно от черновика карточки. CSV включает ответственного, срок и исходный текст,
но не фото и не журнал. Для полной копии нужна резервная копия SQLite. Перед этой миграцией
создана `data/city.before-workflow.sqlite3`.

```powershell
.venv\Scripts\python.exe -m pytest -q
```

Проверяются изоляция учебных данных, валидация, атомарность импорта, отсутствие выдуманного прогноза, расчёт базовой оценки, обновление статуса, кандидаты на дубли и экспорт.
